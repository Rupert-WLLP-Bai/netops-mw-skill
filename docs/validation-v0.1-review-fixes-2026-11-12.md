## Review fixes and checks

- Proxy credential disclosure: curl diagnostic text is withheld when configured HTTP, HTTPS or ALL proxy values contain userinfo; the structured curl exit code and proxy failure classification remain. Real curl tests exercised invalid SOCKS4, SOCKS4a, SOCKS5, SOCKS5h, HTTP, HTTPS and scheme-less proxy values and verified both synthetic credential parts are absent from the four agent-visible outputs and redacted stderr artifacts.
- URL expansion: curl runs with `--globoff`. Real loopback checks verified braces and ranges remain literal, three observed requests equal the three recorded attempts per endpoint, and two endpoints produce six total requests. IPv6 loopback also produced three requests.
- Incomplete 5xx/3xx transfers: real loopback servers sent headers and stalled response bodies; three requests for each status retained the status, curl exit 28 and timeout outcome, with incomplete transfers and a `fault_observed` timeout candidate. Separate replay coverage keeps shared-budget exhaustion distinct from a request timeout.
- Interface context: Linux reads at most 64 KiB from `/proc/net/dev` for the default-route interface within the shared budget. The snapshot records identity, source, timestamp, values and units; missing, unsupported, malformed, oversized or budget-limited inputs are explicit. Sample-input and missing/budget tests exercise this behavior. A single snapshot does not establish rates or load causes.
- Replay comparisons: INET-01 has three normal/pinned HTTPS pairs with explicit shared target, Host, SNI, certificate verification, family, actual and pinned IP, method, direct proxy context, vantage, fresh connection and window. Negative tests reject mismatches and assert expected evidence IDs. INET-06 uses an independent same-target TLS observation, tests its supporting or counterevidence role and rejects unrelated or unverified observations. These are deterministic replay observations; they do not prove causation or resolver CPU responsibility, and the live collector does not generate pinned requests.
