# Skill composition: source review and current audit

**Status:** research, 2026-11-12; this is not a release, an implementation plan, or approval to create skills. See the [suite proposal](network-skill-suite-proposal.md) and its [designed routing cases](network-skill-suite-routing-cases.json). Sources below are primary sources read on 2026-11-12. Repository comparisons are pinned to source commits and describe the inspected files, not the behavior of every host. No upstream code is copied.

## What the format and hosts actually provide

The [Agent Skills specification](https://agentskills.io/specification) defines a directory, `SKILL.md`, required `name` and `description` (both capability and when to use it), and optional resources and metadata. `allowed-tools` is experimental and host support varies. [Authoring guidance](https://agentskills.io/skill-creation/best-practices) favors coherent units, moderate instructions, and on-demand references. It does not define a graph scheduler, native cross-skill calls, automatic retries, durable state, a global budget, or context isolation. A diagram in a skill is guidance, not proof that an engine enforces its edges.

[OpenAI's plugin skills guidance](https://developers.openai.com/plugins/build/skills.md) separates workflows by trigger, inputs and success criteria and describes MCP server dependencies under `dependencies.tools`; those are tool dependencies, not skill edges. [Plugin architecture](https://developers.openai.com/plugins/concepts/plugins.md) allows related skills in a package, with an MCP server only where needed for controlled capabilities. `agents/openai.yaml` is product-specific UI/invocation metadata, not an Agent Skills graph. Neither `dependencies.skills` nor `next_skill` is a standard native orchestration field. Host discovery and actual load behavior require testing on each target host.

The user-invoked local [skill-creator](/home/pejoy/.codex/skills/.system/skill-creator/SKILL.md) is authoritative for this design: assume Codex is capable; add minimal non-obvious guidance, preserve scope, use progressive disclosure only where useful, and make descriptions say what and when. It rejects generic review requirements and compulsory delegation. Its [openai.yaml reference](/home/pejoy/.codex/skills/.system/skill-creator/references/openai_yaml.md) specifies UI metadata, MCP tools and policy, not skill dependencies. Read on 2026-11-12 UTC; SHA-256 respectively `6656e54755638e8efcf275a472b9672eaa8a9a1b9e59dc210e275b03b59e1e66` and `ffac39318e408108141d40f820968e59f70434a891694f9bf1d25be8237b150c`. The local creator says implicit invocation remains enabled by default unless the user explicitly requests explicit-only. Do not change global Codex settings. Its metadata validator checks structure, not decision quality.

The local creator's concise description guidance wins over third-party trigger inflation or rules that say descriptions contain only when, not what. [OpenAI's evaluation guide](https://developers.openai.com/blog/eval-skills.md) distinguishes activation, outcome, process and efficiency and measures traces and artifacts; [Agent Skills evaluation guidance](https://agentskills.io/skill-creation/evaluating-skills) compares clean contexts against no skill or the previous version. An isolated session can substitute when delegation is unavailable or unauthorized.
